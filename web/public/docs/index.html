Introduction

The same reads the Desk app makes, at https://trydesk.trade/api/v1, for anyone to call.

Everything served here is public chain data and public profiles, so there is nothing to sign up for and no key to send. It is read-only: nothing places an order, moves funds or knows a key. Desk’s trading key never leaves the phone it was made on.

All routes answer GET and HEAD; OPTIONS answers 204 for preflight. Every response carries Access-Control-Allow-Origin: * and exposes the rate-limit headers, so a browser can call the API straight from a page.

The envelope

Every successful answer, except health, wraps its payload the same way. meta.asOf is when the server produced the answer; meta.cached is true when it came from the server’s own memo rather than a fresh read.

{
  "data": { ... },
  "meta": {
    "asOf": "2026-09-21T03:06:49.038Z",
    "chain": "monad",
    "cached": false
  }
}

Errors are not wrapped. They are RFC 9457 Problem Details with a stable code; see Error codes.

Where the data comes from

Monad mainnet. Perpl’s public context for the market list, Perpl’s exchange contract for open positions, Perpl’s position events through HyperSync for closed trades, a HyperSync-indexed ledger for wallet history, OKX for candles, balances and prices, and .nad, nad.fun, ENS and Farcaster for names. The API map says which route reads which.

Quickstart

Three steps and no setup.

  1. Pick a route.

    The index lists every route with its tier. Or start from the API map.

    curl https://trydesk.trade/api/v1
  2. Call it.

    No headers are required. Accept: application/json is polite, not necessary.

    curl "https://trydesk.trade/api/v1/traders/top?limit=5"
  3. Read data.

    The payload is under data; meta.asOf says how fresh it is. Anything that is not a 2xx is a problem document with a code to switch on.

    const res = await fetch("https://trydesk.trade/api/v1/traders/top?limit=5");
const body = await res.json();
if (!res.ok) throw new Error(body.code);
console.log(body.meta.asOf, body.data.traders[0].address);

Every endpoint below has a Try it button that runs the request from this page and shows the status, headers and body.

Access & rate limits

No key. Limits are per client IP over a sliding minute, in two tiers.

Tiers

TierLimitRoutes
default60 / minIndex, markets, candles, top traders, identity, token signals, health, stats
expensive10 / minTrader history, wallet resource — both read the chain

Two fixed windows stand in for a sliding one: the previous minute counts in proportion to how much of it still overlaps the last sixty seconds, so a burst at the end of one minute is not forgotten at the start of the next.

Headers

Every answer, including errors, carries the tier’s headers. They are exposed to browsers through Access-Control-Expose-Headers.

HeaderMeaning
X-RateLimit-LimitRequests allowed per minute on this route’s tier.
X-RateLimit-RemainingHow many are left in the current window; 0 when over.
X-RateLimit-ResetUnix seconds when the current window resets.
Retry-AfterOnly on 429: whole seconds to wait before trying again.
Cache-ControlHow long a shared cache may keep the answer. Health and every error are no-store.

Backing off

Wait the seconds in Retry-After, then try once more. Do not retry in a loop without it: the window is a minute, and hammering only keeps Remaining at zero.

async function get(url, attempt = 0) {
  const res = await fetch(url, { headers: { Accept: "application/json" } });
  if (res.status === 429 && attempt < 2) {
    const wait = Number(res.headers.get("Retry-After") ?? 5);
    await new Promise((r) => setTimeout(r, wait * 1000));
    return get(url, attempt + 1);
  }
  return res;
}

Caching

Answers carry a server-side TTL — 10 s for markets, 30 s for the top list and stats, 60 s for the index, candles, history, identity and wallets, 15 s for signals — so a popular answer is often served by the edge without touching your quota, which is why X-RateLimit-Remaining sometimes does not move. Health is memoised on the server for 10 s but sent no-store, so a probe is never answered by a cache. If you need more than the tiers give, cache on your side using meta.asOf and the Cache-Control hints, and open an issue if that is not enough.

Safe inputs

The API takes only things that are already public on chain.

  • Addresses — 0x followed by 40 hex characters, in any case. Anything else is refused with invalid_address before any lookup happens, so a typo never reaches the chain.
  • Market names — letters and digits, 1 to 12 characters, as listed by markets. Case does not matter. Anything else is not a route.
  • Small enumerations — a limit between 1 and 25, a window of 1h, 6h or 24h, a bar from 1m to 1D. Out-of-range values are clamped or refused with invalid_request; each parameter says which.

Never send a private key, a seed phrase, a passkey or a signature. No route accepts one, no route needs one, and no route takes a request body at all. Anything that asks you for those is not this API.

Names are resolved from addresses, never guessed: an ENS or Farcaster name is attached only when that account has verified the address.

Markets

Markets

Every open market on Perpl: mark, 24h change and volume, open interest, TVL, funding, the leverage cap, fees and margin, as plain decimal numbers.

GET /api/v1/markets

Perpl publishes its market list as fixed-point integers at each market’s own scale; this route does the division so a page can print the numbers as they are. Prices come out in the market’s priceDecimals (BTC at one decimal, MON at six), money in the collateral token, and rates as fractions. Markets the venue has closed are left out, so isOpen is always true. The list is the venue: id is the same number the leaderboard’s positions[].marketId carries, and name is what candles takes.

None.

Markets

Candles

Exchange candles for a market’s asset at one of six bar sizes, oldest first, up to 300 of them.

GET /api/v1/markets/{market}/candles

Perpl publishes no candle history, so these are the asset’s own tape on OKX — BTC-USDT for the BTC market, and so on — and the mark the app draws beside them is Perpl’s. Expect the two to sit close but not on top of each other. Each market Desk knows maps to one instrument; a name that matches no instrument answers not_found. The last candle is still forming and moves until its bar closes.

Parameters

market path string required letters and digits · 1 to 12

A market name from markets. Case does not matter; the answer uppercases it. A name with no instrument behind it is refused with not_found; anything that is not letters and digits is not a route. Example: BTC.

BTCETHSOLMONHYPEZECLITPUMP
bar query string optional default 15m

Candle size. Case matters: minutes are lowercase, hours and days uppercase. Anything else is refused with invalid_request. Example: ?bar=1H.

Top traders

Traders on Perpl ranked by unrealised PnL across their open positions, with every position.

The exchange keeps every open position in a list per market; this route pages through all of them, sums each account’s unrealised PnL and sorts. Ties and empty books are ordered by position value so the list is stable between refreshes.

How many traders to return. Values outside the range are clamped, not refused; anything that is not a number falls back to 25. Example: ?limit=5.

Trader history

A trader’s closed trades on Perpl with win rate, profit factor, drawdown, hold time, leverage and a one-line reading of their style.

GET /api/v1/traders/{address}/history

Perpl lists open positions but keeps no trade history, so Desk folds the exchange’s open, close, decrease and liquidation events into one record per account. A wallet with no Perpl account answers stats: null and an empty trades; an account whose events have not been indexed yet answers the same with its accountId filled in.
