# Full audit — 18 September 2026

Six parallel audits (server security, device crypto, concurrency, money maths, performance,
privacy) plus a direct pass over the build, the repository and the live endpoints. Findings
marked **verified** were re-read against the source, and in two cases recomputed by hand,
before being written down. Everything else is reported but not independently confirmed.

**Status, end of 18 September: every finding above is fixed, except the five listed as
accepted at the end.** Each fix is its own commit, with the test that would have caught it
where the code is testable. The server changes are deployed and were checked against the
live endpoints.

---

## What is already right

Worth stating first, because it is most of the codebase:

- **No logging anywhere.** Zero `print`/`NSLog`/`os_log` in the app and the package, zero
  `console.log` in the server. Nothing sensitive can reach a console, a sysdiagnose or a log
  drain, because nothing is written at all. *(verified)*
- **No secret has ever been committed.** No `.env`, `.p8` or `.pem` in the tree or anywhere in
  history. `.gitignore` covers them by pattern. The private key visible in history is the
  published PRF test vector. The app embeds no third-party API key at all. *(verified)*
- **Cron endpoints are authenticated properly**: fail-closed, `timingSafeEqual`, header only,
  checked before the method branch. Live probe returns 401. *(verified)*
- **The install-secret scheme is sound.** 32 random bytes, keychain, device-only, never derived
  from the wallet; only its SHA-256 reaches the server. Nobody can read or rewrite another
  user's subscription. *(verified)*
- **A forged push cannot execute a trade.** Traced end to end: a notification can only pre-fill
  a ticket that still needs a typed amount, a hold-to-confirm and Face ID.
- **Transport is hardened**: redirects refused (so `X-API-Key` can never be replayed to another
  host), ephemeral session, no cookies, no cache, TLS 1.2 floor, https/wss enforced at
  construction, ATS at default with no exemptions. *(verified)*
- **Keychain flags are correct** and nothing sensitive is in the App Group.
- **The EIP-712 signing guard and the Relay deposit validation** — client and edge — are the
  strongest parts of the codebase.
- **Only 9 compiler warnings** with strict concurrency complete, none structural. *(verified)*

## Critical — fix before any real money or a live demo

### C1. A backend hiccup closes every live copy *(verified)*

`web/api/traders.mjs:127-133,270` swallows a chain read failure and returns
`{accountId: null, positions: []}`. `App/Desk/CopyTrader.swift:302-324` sees a non-nil, empty
book, and `CopyPlanner.moves` emits `.closed` for every position the trader had. Real
reduce-only closes are sent for every live copy.

One RPC timeout costs the fee and the slippage on every open copy, and the next poll re-opens
them — a flapping upstream becomes an unbounded fee leak. `alerts.mjs` already has the correct
sibling (`openPosition`, "a missing mark is not a closed position"); the copy path uses the
other one. A test currently blesses the wrong shape (`web/test/traders.test.mjs:101`).

**Fix:** let the server distinguish "unreadable" from "no positions" (502 rather than an empty
book), and on the client require two consecutive readings before acting on a wholesale
disappearance.

### C2. The daily loss limit does not latch *(verified — regression introduced 18 Sep)*

`App/Desk/CopyTrader.swift:481-483` sets `isPaused = true` and calls `persist()`, but
`persist()` no longer writes the pause flag: it moved to the App Group (`AutoCopySwitch`) with
the widget work earlier today. The run loop reconciles 200 ms later
(`CopyTrader.swift:245-251`), flips the flag back to false, and writes a log entry saying
"Auto-copy resumed from outside Desk" — which never happened.

So the safety guard that stops copying after a bad day survives one tick, and the widget,
Siri and Control Center all report copying as running while the app says paused.

**Fix:** call `setPaused(true)` instead of assigning the field.

### C3. The trading socket can wedge until the app is killed *(verified)*

`App/Desk/TradingSession.swift:163` — `defer { connecting = nil }` clears the slot
unconditionally, so a cancelled attempt deregisters a newer one still in flight. The end state
is an authenticated socket with no frame reader: orders go out, answers are never read, every
order reports a stale connection.

**Fix:** `defer { if connecting === attempt { connecting = nil } }`.

## High

### H1. Perpl's contract addresses are not pinned *(verified)*

`DeskKit/Sources/DeskFlow/OpeningSequence.swift:31-32` takes the AUSD token and exchange
addresses from the server's context response, and they go into the `approve` and deposit the
wallet key signs. Relay's depository is pinned (`RelayDeposit.swift:24`); Perpl, which holds the
collateral, is not. Requires Perpl's own gateway to be compromised, or a rogue CA, but the loss
is the user's balance rather than a bad trade.

**Fix:** pin both addresses per network and refuse a context that disagrees.

### H2. The wrong-wallet guard is dead code *(verified)*

`App/Desk/PasskeyCeremony.swift:101` records the freshly derived address before
`App/Desk/AppModel.swift:269` compares against it, so the check always passes. The guard exists
for Apple's synced-passkey bug deriving a different wallet, and it can never fire.

**Fix:** read the stored address before deriving.

### H3. Anyone can fill or starve the alerts table *(verified)*

Nothing proves a device token is real, and there is no rate limit
(`web/api/alerts.mjs:302-329`). ~5,000 junk POSTs fill `MAX_SUBSCRIPTIONS` and every genuine
user then gets "Trade alerts are full" for 60 days. Separately, the scan budget is a *global*
300 addresses (`alerts.mjs:197`), so ~15 junk subscriptions crowd out every real follower
silently.

**Fix:** persist a new subscription only after an APNs send to that token returns 200; budget
the scan per subscription.

### H4. Crash on hostile or absurd numbers *(verified)*

`DeskKit/Sources/DeskFlow/CopyTrading.swift:268` and `App/Desk/CopyTrader.swift:478` convert
unbounded `Double`s straight from the network into `Int`/`Int64`. An absurd entry price traps.
Open copies are persisted, so it can reproduce on every launch.

**Fix:** clamp, and reject non-finite values when building `ObservedPosition`.

### H5. The faucet is drainable *(verified)*

`web/api/faucet.mjs:130` throttles in an in-process `Map` keyed by address — per lambda, so not
a throttle. Fresh addresses drain the wallet. Also a nonce race across concurrent instances.

**Fix:** move the throttle to Redis, key it by address *and* IP.

### H6. Shadow mode overstates the strategy

A shadow copy **cannot be liquidated** (it floors at −margin and can recover), its stops always
fill exactly at the trigger price, those stops only exist while the app is open, it pays no
funding, and it is given a fictional one-million-AUSD balance. For a demo that leads on shadow
results, this is a credibility risk as much as a correctness one.

**Fix:** give `ShadowFill` a liquidation price and terminate there.

### H7. Copies that fill late escape every guard

`App/Desk/CopyTrader.swift:528` gives up after 20 s and records nothing, but the position may
still exist on Perpl. It is then invisible to the open-copy limit, the exposure cap,
`closeWithTrader` and reconciliation — and the user is told "Nothing was opened".

### H8. The copy loop burns the main actor while idle *(verified)*

`App/Desk/CopyTrader.swift:273` publishes the glance every 200 ms regardless of activity; each
publish runs `figures()` four times, each filtering the 400-entry log with
`Calendar.current.isDateInToday` per entry — roughly 8,000 calendar operations a second with
nothing being copied.

**Fix:** hoist the day boundary, cache `Figures`, and publish on change rather than on a tick.

### H9. Every websocket frame invalidates whole screens *(verified)*

`DeskKit/Sources/DeskFlow/LastGood.swift:29` records unconditionally, with no equality check, so
an unchanged price still invalidates every reader — dragging full `Canvas` chart redraws and
non-lazy position lists with it.

## Medium

- **Sign-out deletes nothing** *(verified)*: `AppModel.endSession()` clears only in-memory
  state. Followed traders, nicknames, device token, the 400-entry copy log, the widget glance
  and the keychain items all survive, and the previous account's positions stay on screen until
  the next socket snapshot. The app also never calls the server's `unsubscribe`, so the token
  and follow list sit in Redis for 60 days. *(verified: zero references)*
- **Short liquidation price rounds the wrong way** *(verified by hand)*: `Margin.swift:27-29,43-45`
  rounds a short's liquidation price *up*, showing more headroom than exists. Worked example:
  81,295.8 shown against 81,295.6 true — $0.20. `docs/04-algorithms.md` §9 says round down. The
  long branch is correct, and the existing test uses exactly-divisible inputs so it cannot see
  this.
- **Nothing is marked `.privacySensitive()`** *(verified)*: the widget and Live Activity render
  PnL and trader names on a locked screen.
- **The chase guard compares a mainnet entry to a testnet mark**, so price protection measures
  nothing while trading on testnet, and the logged "vs their entry" figure is a cross-venue
  basis.
- **Copy affordability ignores the fee**, so a copy that costs margin + fee is sent and rejected
  by the venue.
- **`isAffordable` and `hasExpired` are implemented, tested and never called** by the ticket.
- **Guards are per-mode**, so running shadow and live doubles the open-copy and exposure
  budgets.
- **Unresolved losses count as zero forever** in the daily limit, expanding the budget silently.
- **The history index is not idempotent** and its write is not atomic, so a replayed range
  doubles every account's statistics permanently.
- **The trader score is gameable**: two wash-trading accounts can manufacture a score of 100 and
  reach the top of the leaderboard the basket copies from.
- **The Relay quote is validated on what you pay, not what you receive** — `currencyOut` is never
  compared to the token requested.
- **The scan lock has no owner token** *(verified)*, so a slow run can delete the next run's
  lock.
- **The Monad websocket stays open after `stop()`**, and every exchange-wide position event is
  JSON-parsed on the main actor.
- **`OrderTracker` entries and the order-progress buffer are never pruned**, growing for the life
  of the session and costing more per frame as they do.
- **The splash blocks launch for 3.7 s** *(verified: 3100 ms + 620 ms)*, and `TradingShell`'s
  `State(initialValue:)` builds a `MarketModel` (and an un-invalidated `URLSession`) on every
  body pass.
- **The copy log rewrites ~110 KB into UserDefaults on every event** *(verified: 120,801 bytes at
  the 400 cap)*, with a fresh encoder each time.
- **Unauthenticated proxies in front of paid APIs**: `market-stream` holds a 300 s function and
  an OKX socket per connection with no cap; several endpoints are trivially cache-bypassed.

## Low

Redundant `await`/`try` and haptics called from a non-isolated context (9 warnings total); one
`try!` in `MarketModel.swift:69` (provably safe against constant URLs); `unassociated` is dead
code in `TradingSession`; `showsLiveActivity` sits in standard defaults rather than the App
Group; secrets are copied into un-zeroed heap `Data` on every signature; `kSecAttrAccessible` is
not reasserted on keychain update; the follow list travels in a GET query string with a `public`
cache directive; server-supplied image URLs are loaded from any https host; a forged push may
name a trader the user does not follow.

## Suggested order

1. **C1, C2, C3** — each is small, and each can cost money or a demo.
2. **H4, H2, H8** — a crash, a dead guard, and the always-on main-actor cost.
3. **H3, H5** — server abuse, before the submission is public.
4. **H1, H6, H7** — pinning, shadow honesty, the lost-copy hole.
5. The privacy set: sign-out cleanup, `unsubscribe`, `.privacySensitive()`.
6. The performance set: `LastGood` equality, the splash, the log persistence.

## Accepted, not fixed

Recorded deliberately rather than left unnoticed:

- **Shadow copies pay no funding.** A copy held over 43 minutes diverges from the live
  equivalent by the funding leg. Modelling it needs a rate history the app does not keep.
- **Guards are per mode.** Running shadow and live at once gives each its own open-copy and
  exposure budget. Shadow exposure is imaginary, so the live half stays bounded; the doc
  comment is what was wrong, not the behaviour.
- **No certificate pinning.** The reasoning in `HTTPTransport` still holds — a pin that
  outlives a venue's rotation bricks the app with no kill switch — and pinning the contract
  addresses closes the case that actually cost money.
- **`readBooks` reads at most 20 traders.** The server caps the request at the same number,
  so raising it is a change on both sides.
- **The trader score cannot detect wash trading.** Volume and market spread raise the cost
  of a manufactured record; telling one from a real one needs the counterparty, which these
  events do not carry.

## What the fixes cost, and what they changed on screen

- Auto-copy no longer closes on a single bad read, so a full close takes one extra cycle to
  act on.
- Turning alerts on now depends on Apple accepting the confirmation push; if it does not,
  alerts are refused rather than silently stored.
- The leaderboard re-ranks: the score now needs notional and more than one market behind it.
- The launch overlay is 1.5 s rather than 3.7 s.
